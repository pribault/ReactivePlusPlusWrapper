Detailed Description

template<detail::Value T>
class rppw::Observable< T >

Cold source of zero or more values, followed by completion or an error.

Template Parameters
TUnqualified value type satisfying std::copyable.

Each subscription executes its own chain. Composing operators does not invoke producers. Without an explicit scheduler, synchronous processing runs on the thread calling subscribe(). Producer and operator exceptions are forwarded through std::exception_ptr. An error or completion terminates the subscription; no further events are delivered. Reactive objects are copyable and share their type-erased RPP representation, which may allocate. Operators return a new chain.

Warning
Reference captures must outlive their use, including asynchronous use. The caller must synchronize data shared between subscriptions. No backpressure mechanism is provided.

◆ merge() [2/2]

template<detail::Value T>
template<concepts::ObservableSourceRangeOf< T > R>
Observable rppw::Observable< T >::merge ( R && sources,
std::size_t maxConcurrency )
static

Merges sources with at most maxConcurrency active subscriptions at a time.

Template Parameters
RInput range of Observable<T>, Single<T> or Maybe<T>.
Parameters
sourcesHomogeneous range copied into owned storage immediately.
maxConcurrencyPositive subscription limit, applied separately to each subscriber.
Returns
Observable forwarding all values and completing when all sources complete. An empty range completes without values; empty Maybes contribute no values.
Exceptions
std::invalid_argumentIf maxConcurrency is zero.

Each completed source frees a slot for a waiting source. A limit of one subscribes to sources sequentially. Reserving a slot admits its source. An error prevents new reservations before notifying onError. Active subscriptions are disposed when onError returns. Cancellation disposes active subscriptions and prevents further reservations. A source that reserved its slot on another thread just before an error or a cancellation may still enter its producer. Notifications are serialized without blocking: one raised while another of this subscription is being delivered, from any thread, is queued and delivered in order by the delivering thread once its callback returns. A callback may therefore run on the thread of another source, and the queue is unbounded. Slots freed meanwhile are refilled on that thread once its queue is empty, outside any callback, so a refilled synchronous source is delivered as it emits. No worker thread is added, and the limit does not throttle values. Range traversal and allocation exceptions are synchronous.
